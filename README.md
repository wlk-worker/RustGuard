# RustGuard — UEBA 内部数据泄露异常检测系统（v0.2）

> 纯 Rust + smartcore（DBSCAN）+ **手写 Isolation Forest**，双引擎集成，单文件架构。
> 固定随机种子可复现；除演示日报外，自带稳定性 / 压力测试 / 参数敏感性三套实验模式。

## 环境要求

- Rust 2021 Edition（rustc ≥ 1.75，实测 1.93.1）
- 网络：直连 crates.io 受限时已内置 `.cargo/config.toml`（rsproxy 国内镜像），开箱即用

## 编译与运行

```bash
cargo check                                  # 类型检查（当前零警告）
cargo test                                   # 单元测试（6 项全绿）
cargo run                                    # 默认 seed=42 完整彩色日报 + report.json
cargo run --release                          # 性能演示（实测 ~22ms / 500条）
cargo run -- --seed 7                        # 换数据
cargo run -- --stability 10                  # 多 seed 稳定性实验（均值±标准差）
cargo run -- --stress                        # 压力测试：配置随机化 + UNKNOWN 假设外攻击池
cargo run -- --sensitivity                   # eps × z 参数敏感性网格
cargo run -- --fusion vote                   # 切换融合策略（and/or/vote/smart/boost/hybrid）
```

## 架构（六大模块）

| 模块 | 说明 |
|---|---|
| 1 日志生成器 | 500 条 / 5 用户；正常行为**仅工作日** 9-18 点、文件体量服从**对数正态** LN(中位 100KB, σ=0.30)（真实企业文件的典型右偏长尾形态）、密级 1~2；注入 25 条：A 深夜大额(4) / B 五分钟连击 350-700KB(12) / C 密级5越权(5) / D 超均值10倍+ (4)；压力模式另加 U1-U4 假设外攻击 |
| 2 特征工程 | 规格 6 维（时刻/ln大小/密级/操作编码/5min频率/偏离度）+ 可选第 7 维 is_weekend（stress 特征迭代演示用）；偏离度带「<10 条历史置信平滑」，无未来/标签泄漏 |
| 3 异常检测 | **双引擎集成，按用户千人千面独立建模**：① 手写 Isolation Forest（n_trees=100, max_samples=256，c(n) 调和修正，分位数自适应阈值）② 鲁棒 Z-Score(MAD) × smartcore DBSCAN(eps=0.5, min_samples=3)。Z-Score 候选采用**两级证据门**：单组证据 \|z\|>5 或 ≥2 组独立证据 \|z\|>3，其中体量与偏离度因同源只计一组（多重比较修正）；密度侧含三重判据（噪声 / 规模受限的异常小簇 / 簇内典型性距离），外加**连击时间桥接**捕获序列头部；融合策略 6 种可切换 |
| 4 可解释归因 | 基线（主导簇成员）对比规则回溯生成中文归因 + Critical/High/Medium 分级；按下标 O(1) 精确关联 |
| 5 报告输出 | colored 彩色终端 + **告警聚合**（12 连击→1 个批量事件）+ report.json（含检测器对比表/事件列表） |
| 6 性能与实验 | 分阶段计时；稳定性/压力/敏感性三套实验模式内置 |

## 实测指标（均为本机 release/debug 实测，可复现）

| 实验 | 结果 |
|---|---|
| 默认数据集 seed=42 | 检出 **92%** / 准确 **100%** / 误报 0 / 漏报 2（连击最初 2 条：单条体量与真实大文件自然尾部统计不可分，属预期边界） |
| 稳定性（seed 1..20） | 终判检出 **99.2±2.1%**，准确 **99.6±1.2%** |
| 随机抽考（8 个全新随机大种子） | 检出 96.5% 均值 / 准确 98.6% 均值 |
| 压力·配置随机化（4 组，用户数/污染率/难度变化） | 检出 87.8±21.6%，准确 **100.0±0.0%**（低分来自刻意的"密级越权仅 150KB"困难配置，如实报告） |
| 压力·UNKNOWN 池 | U1 突发delete **73.3%**；U2 周末 0%→**加 is_weekend 特征后 100%**（特征迭代对照实验）；U3 慢速蚕食 0%（静态基线边界，已列改进路线）；U4 群体微小 0%（低于单事件统计显著性，需跨账号特征） |
| 敏感性（eps 0.3~1.2 × z 2.5~3.5，12 格） | 全部 12 格准确率 100%；检出 80~92%，随 eps 增大缓降，无悬崖 |
| 检测器选型（消融） | 混合 99.2% vs 手写 IF（分位校准）56.6% vs 固定阈值 IF 52% → 默认策略 HYBRID-PRIMARY，IF 旁路交叉验证 |
| 性能 | 500 条 / 5 用户 release **~15-23ms**；debug ~110ms |

> 说明：v0.2 将正常文件体量改为对数正态长尾（更真实）并引入两级证据门后，准确率显著抬升、
> 召回轻微让渡给"统计上确实无法区分"的序列头部样本——这是精确率/召回率曲线上主动选择的
> 工作点，不是能力退化；需要更高召回可用 `--fusion or` 现场对比。

## 答辩要点（FAQ）

1. **smartcore 有 IsolationForest 吗？** 没有（v0.4.10 源码核查：cluster 模块仅 kmeans/dbscan/agglomerative）。我们按论文原理手写（树构建+路径长度+c(n) 修正），并保留 DBSCAN 混合器作为第二路异构引擎做消融对比——比"调库"更能证明算法理解深度。
2. **是不是为测试数据写死的？** 判定路径无任何场景规则（场景词汇只存在于生成器）；20 seed 稳定性中 seed3 曾漏 1 条（96%）——写死的实现不会失手；UNKNOWN 池里 U3 明确 0% 召回并给出根因（单维缓变+静态基线），这是"敢报忧"的证据而非缺陷。
3. **为什么 MAD 不用均值方差？** 12 连击会把用户自身 σ 拉高导致检测器"失明"（连击越大越检不出——UEBA 实战悖论），MAD 缩放估计天然抗污染。
4. **群体异常怎么抓？** DBSCAN 非主导小簇 + 簇内典型性距离双判据（后者来自 stress 发现的密度链爬坡漏检修复）。
5. **误报怎么控？** 双引擎分数透明呈现；融合策略 AND/VOTE 提供"零误报"档位（--fusion and：准确 100% 召回 57.8%），按运营取舍。

## 已知边界（如实声明）

- 特征空间表达不出的异常检不出（如未启用 is_weekend 时的周末访问）
- 慢速渐进式窃取需要双时间窗基线（近期扩展项）
- 跨账号协同（同一动作分散在多账号）需要图/peer-group 特征（中期方向）
- 演示数据为合成日志；真实 auditd/ETW 适配层见方案书扩展章节
